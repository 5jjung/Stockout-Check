# 시즌신상품절체크

구글 시트 **상품등록** 탭에 등록된 시즌 신상품을 무신사에서 주기적으로 확인하고,
품절·재입고가 생기면 시트에 기록하고 슬랙으로 알려줍니다.

## 폴더 구조

```
시즌신상품절체크/
├─ src/
│  ├─ index.js      실행 시작점 (한 번 확인 / 계속 감시)
│  ├─ config.js     설정 (탭 이름, 간격, 동시 조회 수 …) ← 바꿀 건 여기만
│  ├─ sheets.js     구글 시트 읽기·쓰기
│  ├─ musinsa.js    무신사 상품 페이지 조회 (브라우저)
│  ├─ stock.js      품절 판정 규칙
│  ├─ slack.js      슬랙 알림
│  └─ time.js       한국시간
├─ scripts/probe.js 상품 하나 점검 도구
├─ test/            판정 규칙 테스트
└─ .github/workflows/stock-check.yml   10분마다 자동 실행
```

## 시트 사용 방법

| 탭 | 역할 | 코드가 쓰나? |
|---|---|---|
| 시즌설정 | 시즌별 감시 ON/OFF. **ON인 시즌만** 확인 | 읽기만 |
| 상품등록 | 상품 목록, D열 감시 체크, F열부터 사이즈 체크 | 읽기만 |
| 26FW (시즌 탭) | 상품별 현재 상태. 매번 갱신 (없으면 자동 생성) | 씀 |
| 품절_알림기록 | 변동이 생길 때마다 한 줄씩 추가 | 씀 |
| 통합이력 | 같은 내용 + 시즌·상품번호 | 씀 |

### 체크박스 규칙 (재입고 일정 없음)

| 상품등록 | 의미 | 코드 동작 |
|---|---|---|
| D열 체크 | 감시 대상 | 품절/재입고 → **기록 + 슬랙** |
| D열 체크 해제 | 재입고 일정 없는 상품 | 계속 확인함. 변동은 `(재입고 일정 없음)` 표시로 **기록만** |
| 사이즈 칸 체크 해제 | 그 사이즈는 재입고 일정 없음 | 위와 같음 (사이즈 단위) |
| 사이즈 칸 빈칸 | 원래 없는 사이즈 | 무신사에 생기면 감시 대상으로 봄 |

재입고 일정이 없던 상품·사이즈에 **재고가 다시 생기면** 슬랙으로 알려줍니다.
상품등록의 체크박스를 다시 켤지 판단하시면 됩니다.

시즌 탭의 **품절 옵션** 칸에는 재입고 일정 없는 사이즈가 `S(일정없음)`처럼 표시됩니다.

### 기록되는 종류

`품절 발생` · `재입고` · `옵션 삭제` · `전체 품절` · `판매 중지` · `상품 삭제됨` · `판매 재개` · `최초 확인`
(재입고 일정 없는 항목은 뒤에 `(재입고 일정 없음)` / `(재입고 일정 없던 항목)`이 붙습니다)

- `최초 확인`: 처음 확인한 상품이 이미 품절이면 기록만 남깁니다 (슬랙 X).
- 조회에 실패한 상품은 기존 값을 그대로 두고 **마지막 확인** 칸에만 실패 이유를 적습니다. (잘못된 품절/재입고 기록 방지)
- 직전 상태는 시즌 탭에 적힌 값으로 비교하므로 별도 저장 탭이 없습니다.

## 처음 설정

1. **구글 서비스계정 키** 준비 (기존 모니터링에서 쓰던 키 그대로 사용 가능)
2. 구글 시트 **공유**에 서비스계정 이메일(`…@….iam.gserviceaccount.com`)을 **편집자**로 추가
3. GitHub 저장소 → Settings → Secrets and variables → Actions → **New repository secret**

   | 이름 | 값 |
   |---|---|
   | `SPREADSHEET_ID` | 시트 주소의 `/d/` 와 `/edit` 사이 값 |
   | `GOOGLE_SERVICE_ACCOUNT_JSON` | 서비스계정 키 파일 내용 전체 |
   | `SLACK_WEBHOOK_URL` | (선택) 슬랙 웹훅 주소 |

4. Actions 탭 → **시즌 신상품 품절 체크** → Run workflow (`dry_run` 체크하면 쓰기 없이 미리보기)

> ⚠️ 퍼블릭 저장소입니다. 키 파일·`.env`는 절대 올리지 마세요 (`.gitignore`에 이미 막아 둠).

## 실행 방법

### 1) GitHub Actions (자동, 10분마다)
설정만 하면 자동으로 돕니다. GitHub 예약 실행은 최소 5분 간격이고, 혼잡할 땐 몇 분씩 늦어질 수 있습니다.

### 2) PC에서 실시간 감시 (더 짧은 간격)

```bash
npm install
npx playwright install chromium
cp .env.example .env        # SPREADSHEET_ID 등 채우기, credentials.json 은 이 폴더에
npm run watch               # INTERVAL_MINUTES(기본 5분)마다 계속 확인, Ctrl+C로 종료
```

| 명령 | 설명 |
|---|---|
| `npm run check` | 한 번 확인 |
| `npm run watch` | 계속 확인 |
| `npm run dry` | 시트·슬랙에 쓰지 않고 결과만 출력 |
| `npm run probe -- 6885281` | 상품 하나에서 무신사가 보낸 데이터 확인 |
| `npm test` | 판정 규칙 테스트 |

## 조회가 전부 실패할 때

무신사는 프로그램의 직접 요청을 막기 때문에, 이 코드는 실제 브라우저로 상품 페이지를 열어서
페이지가 받아오는 데이터를 읽습니다. 그래도 막히면 아래 순서로 확인하세요.

1. `npm run probe -- 6885281` 로 어떤 응답을 받는지 확인
2. GitHub 서버에서만 막히는 경우 → 회사 PC에서 `npm run watch`
3. PC에서도 막히면 `.env`에 `HEADLESS=false`, `BROWSER_CHANNEL=chrome` (PC 크롬으로 창을 띄워 확인)
4. 재고 데이터 주소가 바뀐 경우 → probe 결과의 주소를 `src/musinsa.js`의 보충 요청에 반영
