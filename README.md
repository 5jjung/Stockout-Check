# 시즌신상품절체크

구글 시트 **상품등록** 탭에 등록된 시즌 신상품을 무신사에서 주기적으로 확인하고,
품절·재입고가 생기면 시트에 기록하고 슬랙으로 알려줍니다.
GitHub Actions에서 10분마다 돌기 때문에 컴퓨터가 꺼져 있어도 동작합니다.

## 동작 방식

```
사무실 PC 크롬 (무신사 탭 열어 둠)            GitHub Actions (10분마다, PC 꺼져도 동작)
  └ 수집 스크립트(Tampermonkey)                 ├ 브랜드 목록 → 상품 전체 품절 확인
      10분마다 감시 상품의 사이즈별 재고 확인     ├ '브라우저_수집' 읽기 → 사이즈별 품절 확인
      → 시트 '브라우저_수집' 탭에 적음  ───────▶ └ 26FW 탭 갱신 · 품절_알림기록 · 통합이력 · 슬랙
```

- 크롬 수집이 **40분 이내**면 사이즈별로, 그보다 오래됐거나 없으면 **상품 전체 품절만** 확인합니다.
- PC가 꺼져 있어도 상품 전체 품절은 계속 잡힙니다. 사이즈 품절은 PC가 다시 켜지면 이어서 잡힙니다.

## 10분 자동 실행 (구글 시트가 GitHub를 실행)

GitHub 자체 예약 실행은 늦거나 건너뛸 때가 있어, 구글 시트(Apps Script)가 10분마다 GitHub 품절 체크를 실행합니다. 컴퓨터가 꺼져 있어도 동작합니다.

1. GitHub 토큰 만들기: GitHub → Settings → Developer settings → Fine-grained tokens → Generate new token
   - Repository access: **Only select repositories → Stockout-Check**
   - Permissions → Repository permissions → **Actions: Read and write**
2. 시트 메뉴 **품절 체크 → ① GitHub 연결 (토큰 입력)** → 토큰 붙여넣기
3. **품절 체크 → ② 10분 자동 실행 켜기**

## 크롬 수집 설정 (처음 한 번)

1. **Apps Script 웹앱**
   1. 구글 시트 → 확장 프로그램 → Apps Script
   2. [`apps-script/Code.gs`](apps-script/Code.gs) 내용을 전부 붙여넣고 저장
   3. 위쪽 함수 선택에서 `setup` → 실행 → 권한 허용 → 실행 로그의 **토큰** 복사
   4. 배포 → 새 배포 → 유형 **웹 앱**, 실행 **나**, 액세스 **모든 사용자** → 배포 → **웹 앱 URL** 복사
2. **Tampermonkey 스크립트**
   1. Tampermonkey 아이콘 → 새 스크립트 만들기
   2. [`chrome/codegraphy-stock-collector.user.js`](chrome/codegraphy-stock-collector.user.js) 내용을 전부 붙여넣기
   3. 저장 후 Tampermonkey 메뉴 → **설정 입력 (웹앱 주소·토큰)** → 1번에서 복사한 값 입력
   4. 스크립트는 GitHub에서 자동 업데이트됩니다 (설정은 유지됨)
3. 사무실 PC 크롬에서 **무신사 탭 하나를 열어 둡니다.** 오른쪽 아래에 `품절수집 · …` 상태가 보이면 정상입니다.
   바로 확인하려면 Tampermonkey 메뉴 → **지금 바로 수집**.

> 토큰과 웹앱 URL은 저장소에 올리지 마세요 (Tampermonkey 안에만 저장).

## 폴더 구조

```
시즌신상품절체크/
├─ src/
│  ├─ index.js      실행 시작점 (한 번 확인 / 계속 감시)
│  ├─ config.js     설정 (탭 이름, 간격, 동시 조회 수 …) ← 바꿀 건 여기만
│  ├─ sheets.js     구글 시트 읽기·쓰기
│  ├─ listing.js    무신사 브랜드 목록으로 상품 전체 품절 확인
│  ├─ browser-data.js 크롬 수집 결과(사이즈별 재고) 읽기
│  ├─ musinsa.js    무신사 상품 페이지 조회 (브라우저)
│  ├─ stock.js      품절 판정 규칙
│  ├─ slack.js      슬랙 알림
│  └─ time.js       한국시간
├─ chrome/         크롬 수집 스크립트 (Tampermonkey)
├─ apps-script/    시트 ↔ 크롬 연결 웹앱 (Apps Script)
├─ scripts/probe.js 상품 하나 점검 도구
├─ test/            판정 규칙 테스트
└─ .github/workflows/stock-check.yml   10분마다 자동 실행
```

## 시트 사용 방법

| 탭 | 역할 | 코드가 쓰나? |
|---|---|---|
| 시즌설정 | 시즌별 감시 ON/OFF. **ON인 시즌만** 확인 | 읽기만 |
| 상품등록 | 상품 목록, D열 감시 체크, F열부터 사이즈 체크 | 읽기만 |
| 26FW (시즌 탭) | 상품별 현재 상태. 매번 갱신 (없으면 자동 생성) | 씀 |
| 품절_알림기록 | 변동이 생길 때마다 한 줄씩 추가 | 씀 |
| 통합이력 | 같은 내용 + 시즌·상품번호 | 씀 |

### 체크박스 규칙

| 상품등록 | 코드 동작 |
|---|---|
| D열 체크 | 감시 대상. 품절/재입고 → **기록 + 슬랙** |
| D열 체크 해제 (재입고 일정 없음) | **확인하지 않음.** 시즌 탭에는 `⏸ 감시 안 함`으로만 표시 |
| 사이즈 칸 체크 | 그 사이즈 품절을 감시 |
| 사이즈 칸 체크 해제 (재입고 일정 없음) | 그 사이즈는 **무시** |
| 사이즈 칸 빈칸 | 원래 없는 사이즈. 무신사에 생기면 감시 대상으로 봄 |

### 재고 부족 알림 (입고 예정 상품)

시트 **입고일정** 탭에 앞으로 입고 일정이 있는 사이즈의 남은 재고가 **5개 이하**가 되면 슬랙으로 따로 알립니다.
예: `📦 입고 예정 상품 재고 5개 이하` · `M 3개 남음 (입고 12/11 · 예약발송 12/18)`
- **입고일정 탭**: 예약발송 SKU 파일의 표(제목줄 + 앞으로의 일정 줄)를 그대로 붙여넣습니다. 제목 `제품명 / 사이즈 / 예약발송일 / 입고예정일` 이 있어야 하고, `종료여부=종료` 나 지난 일정은 자동으로 빠집니다.
- 제품명은 상품등록의 상품명과 띄어쓰기·`-`·`_` 를 무시하고 맞춥니다. 제품명에 색상이 없으면 컬러 코드로 찾습니다. 못 찾은 이름은 실행 기록에 표시됩니다.
- 입고일정은 내부 정보라 저장소에는 올리지 않고 시트에만 둡니다.
- 시즌 탭 J열 **재고 적은 옵션**에 `M(3), L(5)`처럼 표시됩니다.
- 같은 사이즈는 한 번만 알립니다 (재고가 다시 늘었다가 줄면 다시 알림).
- 크롬 수집에 남은 수량 정보가 있을 때만 동작합니다. 기준 수는 `LOW_STOCK_LIMIT`, 모든 사이즈를 보려면 `LOW_STOCK_SCOPE=all`.

### 기록되는 종류

`품절 발생` · `재입고` · `재고 부족` · `옵션 삭제` · `전체 품절` · `판매 중지` · `상품 삭제됨` · `판매 재개` · `최초 확인`

- `최초 확인`: 처음 확인한 상품이 이미 품절이면 기록만 남깁니다 (슬랙 X).
- 조회에 실패한 상품은 기존 값을 그대로 두고 **마지막 확인** 칸에만 실패 이유를 적습니다.
- 직전 상태는 시즌 탭에 적힌 값으로 비교하므로 별도 저장 탭이 없습니다.

## 처음 설정

1. **구글 서비스계정 키** 준비 (기존 모니터링에서 쓰던 키 그대로 사용 가능)
2. 구글 시트 **공유**에 서비스계정 이메일(`…@….iam.gserviceaccount.com`)을 **편집자**로 추가
3. GitHub 저장소 → Settings → Secrets and variables → Actions → **New repository secret**

   | 이름 | 값 |
   |---|---|
   | `SPREADSHEET_ID` | 시트 주소의 `/d/` 와 `/edit` 사이 값 |
   | `GOOGLE_SERVICE_ACCOUNT_JSON` | 서비스계정 키 파일 내용 전체 |
   | `SLACK_WEBHOOK_URL` | (선택) 슬랙 웹훅 주소 |

4. Actions 탭 → **시즌 신상품 품절 체크** → Run workflow (`dry_run` 체크하면 쓰기 없이 미리보기)

> ⚠️ 퍼블릭 저장소입니다. 키 파일·`.env`는 절대 올리지 마세요 (`.gitignore`에 이미 막아 둠).

## 실행 방법

### 1) GitHub Actions (자동, 10분마다)
설정만 하면 자동으로 돕니다. GitHub 예약 실행은 최소 5분 간격이고, 혼잡할 땐 몇 분씩 늦어질 수 있습니다.

### 2) PC에서 실시간 감시 (더 짧은 간격)

```bash
npm install
npx playwright install chromium
cp .env.example .env        # SPREADSHEET_ID 등 채우기, credentials.json 은 이 폴더에
npm run watch               # INTERVAL_MINUTES(기본 5분)마다 계속 확인, Ctrl+C로 종료
```

| 명령 | 설명 |
|---|---|
| `npm run check` | 한 번 확인 |
| `npm run watch` | 계속 확인 |
| `npm run dry` | 시트·슬랙에 쓰지 않고 결과만 출력 |
| `npm run probe -- 6885281` | 상품 하나에서 무신사가 보낸 데이터 확인 |
| `npm test` | 판정 규칙 테스트 |

## 조회가 전부 실패할 때

무신사는 프로그램의 직접 요청을 막기 때문에, 이 코드는 실제 브라우저로 상품 페이지를 열어서
페이지가 받아오는 데이터를 읽습니다. 그래도 막히면 아래 순서로 확인하세요.

1. `npm run probe -- 6885281` 로 어떤 응답을 받는지 확인
2. GitHub 서버에서만 막히는 경우 → 회사 PC에서 `npm run watch`
3. PC에서도 막히면 `.env`에 `HEADLESS=false`, `BROWSER_CHANNEL=chrome` (PC 크롬으로 창을 띄워 확인)
4. 재고 데이터 주소가 바뀐 경우 → probe 결과의 주소를 `src/musinsa.js`의 보충 요청에 반영
